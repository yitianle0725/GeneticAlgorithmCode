# IE-MOEO 机制实验登记与执行方案

本方案针对 `iemoeo_pilot_200n_v1` 分析后仍未解决的主张。目标是估计机制的贡献和适用边界，允许得到负面或不确定结论，不能把“确保验证有贡献”作为实验目标。即使算法超过七种参照，也不能代替归因实验。S3-Elite 含有多种机制，只作性能参照。

## 已有证据与待检验解释

原 pilot：16 问题 × M=3/4/10 × seeds 1–5 × 8 算法，共 1920 项，全部完成。IE-MOEO 的均值排名为 6.9167/8，中位数排名为 6.8125/8；WFG4 M10 中位数第一是开发集个例。邻域检查在 7823 轮中仅 100 轮拒绝亲本，206/240 次运行完全没有拒绝；组合只占约 2.98% FE。具体统计见 [结果分析](iemoeo_pilot_200n_v1_analysis.md)。

需要检验的解释包括：相同标量权重可能使岛内搜索趋同；局部一代是否不足；重建消耗是否挤占组合预算；参考方向选择是否承担了主要的覆盖维护。以上均不能由现有观察直接证明因果。

## 第一优先级：可直接运行的八组实验

所有组只调用现有 IE-MOEO 核心，不调用其他性能参照算法。各个两两主效应对照只改变一个配置字段。

| 组 | 与完整版本的差别 | 用途 |
|---|---|---|
| full | 无 | 当前完整版本，共同锚点 |
| shared | `--no-isolation` | 独立交配对共享交配；仍保留岛内更新，不等同所有个体完全混合的另一种算法 |
| rank | `--no-diversity-maintenance` | 去掉 NSGA-III 参考方向维护，末层随机截断 |
| shared_rank | 同时共享交配和关闭参考方向维护 | 与 full/shared/rank 构成 2×2 |
| unchecked | `--no-parent-check` | 邻域代表资格检查的贡献 |
| sbx | `--combination-method sbx_only` | 整块继承相对 SBX 的贡献，保留变异和修复 |
| random_coord | `--combination-method random_coord` | 整块继承相对逐坐标继承的贡献 |
| shared_sbx | 共享交配且用 SBX | 与 full/shared/sbx 构成第二个 2×2 |

关键对照：

1. full 对 shared：独立交配的总效应。核查 `foreign_parent_count` 确实从零变为非零，同时看 IGD+、HV、方向覆盖、归一化决策距离及解集大小。
2. rank 对 shared_rank：不借助参考方向维护时的独立交配效应。full 对 rank 则检验是否仍依赖显式多样性维护。
3. full 对 unchecked：只检验邻域资格筛选。首先统计检查是否触发，拒绝率、保底率、亲本数量是否改变；未触发时不能宣称其贡献。
4. full 对 sbx、random_coord：区分结构化继承和普通重组/逐坐标重组。总 FE 一致，同时记录实际组合 FE、重复候选和组合阶段占比，不能把总预算一致写成各阶段预算完全一致。
5. 两个 2×2：独立交配×参考方向维护、独立交配×结构化组合。用同 seed 的 log IGD+ 差中差估计交互，避免用两个单独优胜结果推断协同。

## 分阶段执行

| 阶段 | 问题 | M | seeds | FE | core 任务数 | 状态/门槛 |
|---|---|---|---|---|---:|---|
| smoke | DTLZ2、WFG9 | 3 | 1 | 20N | 16 | 已完成；只验证运行和开关，不做效能结论 |
| pilot | DTLZ2/3/7、WFG3/6/9 | 3/4/10 | 1–5 | 200N | 720 | 已登记；先核查激活、失败和 FE，再解释描述性趋势 |
| confirm | 同 pilot | 3/4/10 | 31–60 | 400N | 4320 | pilot 后冻结实现/全部登记对照，使用新 seeds；结果需包含负面场景 |
| many_objective | 同 pilot | 5/8/15 | 31–60 | 400N | 4320 | 若保留广泛 many-objective 主张，必须补充；不能从 M10 推断 M15 |
| timing | DTLZ2、WFG9 | 3/10 | 31–35 | 200N | 160 | 强制 workers=1、timing-only；仅初步内核耗时控制 |

问题覆盖规则前沿、多峰/断裂前沿、退化前沿及变量关联困难问题；选择基于已知性质和本次开发诊断，不属于独立未知问题验证。确认集的随机种子独立，但问题家族不独立。若要主张跨问题泛化，还需预先登记新问题家族或留出问题。

旧 pilot 的 IE-MOEO 没有源码摘要，不能仅凭同名就当成新机制组的严格同版本锚点。第一轮 full 使用当前冻结核心建立；建立后 full 可在 core/sensitivity 套件间复用。其他七种性能参照均不在本机制队列中，不会被重跑。

pilot 的 5 seeds 不适合显著性确认。不能为了得到 p<0.05 反复追加 seed 或只保留有利问题。确认阶段不按 pilot 的显著性筛掉负面场景。若因诊断而修改算法，另开新 output-root、保留旧登记和所有结果，再冻结确认版本。

## 第二优先级：敏感性与候选池控制

`--suite sensitivity` 包含 full 和以下八组，pilot 共 810 项。full 的共享结果可自动复用，不会再计算一次。

- 半径 0.05、0.2、1.0：检验检查是否因为决策邻域过小而不触发。大半径仅是激活诊断，不能选出最好半径后用同 seeds 宣称成功。
- 局部代数 3、5：确认是否需要更充分的局部竞争。固定总 FE 后外层轮数、重建及组合比例会变化，这是调度敏感性，不能解释成纯粹的“多两代”效应。
- uniform_2 与 known_2：都保持两块，仅改变分块方式，避免四块均匀切分与位置/距离两块之间的块数混杂。WFG 的已知位置/距离分组不意味着数学完全可分。
- representatives_only：关闭非代表局部个体候选池，测工程性候选保留的贡献。若候选不足导致失败，按失败报告，不能默默缩小 P。

## 尚缺实现的必要对照，不能被现有 flags 替代

| 主张 | 必须补充的控制 | 当前证据限制 |
|---|---|---|
| 局部竞争所得极值亲本优于只看高适应度 | 每岛最佳代表 vs 每岛随机代表 vs 联合池标量最佳代表；相同 FE、相同亲本数量上限、相同后续选择 | unchecked 保留了局部最佳代表选择，只关闭邻域检查，不能代表整个亲本选择机制 |
| 独立进化替代拥挤距离并减少“错杀” | 同一核心中隔离开关×真实 rank-and-crowding 的 2×2；记录目标距离近、决策距离远的个体保留率 | rank 是随机截断，参考方向也不是拥挤距离；NSGA-II 外部对比不能代替这一控制 |
| 跨岛极值组合本身有效 | 无组合、但将等量 FE 明确重新分配到局部搜索的版本；分配规则预先固定 | SBX 仍在组合两个亲本，能检验整块结构，不能检验有无组合 |
| 小群体代表是数学极值/驻点 | 明确局部最优/KKT 条件、额外探测费用及认证测试 | 一代局部优化及有限代表邻域非支配检查都不能证明数学极值 |
| 岛内并行效率/低复杂度 | 实现岛内并行，固定硬件/FE，1/2/4/8 核加速、通信开销、规模增长曲线 | workers 只是实验任务并行；记录时间降低也不等于复杂度阶数降低 |
| 网络调度、DRL 协同有效 | 网络约束、动态流量、去掉全局优化/去掉 DRL/去掉预测的联合消融 | DTLZ/WFG 不能确认应用层主张 |

这些控制在 JSON 中登记为 `pending_controls`，调度器不会假装它们已经可执行。当前版本不改动生产算法来追求正面结果，也不把未实现的对照混入结论。

## 指标、统计与判定规则

- 主要质量指标为 IGD+；HV 为补充。对本套件全部登记两两对照、场景及 IGD+/HV 联合执行 Holm 校正，α=0.05。交互单独作为事先登记的检验族执行 Holm 校正。
- 同 seed 配对，记录配对胜率、配对差值中位数、IGD+ 配对对数比，以及 A12。A12 是分布优势概率，不能代替配对效应。不同问题的原始 IGD+ 不直接求跨问题平均。
- 交互量为 `[log(A)-log(B)]-[log(C)-log(D)]`，零值下限固定为 1e-12；负值表示隔离在第一种条件下相对更有利，不直接证明任意问题上的协同。
- 方向覆盖、归一化决策距离、GD+、最终解数用于解释机制，目前汇总中仅作描述。决策距离按变量边界归一化，固定采样种子，最多 2000 对，单解集定义为 0。
- 最终解数会影响覆盖与 HV。补充等基数分析时必须对双方使用同一预登记抽样规则，并报告完整结果；若某组只剩一个解，不能删去该运行或只报告其余结果。
- 机制支持需要同时有正确的开关激活、预登记对照中的方向和效应证据，并在独立 seeds 下可重复。反向结果应收缩主张；不显著不能写成等效，等效/非劣需另定实际意义界限及检验。
- 单次质量更好不构成因果证据；总 FE 相同不代表 CPU 相同。时间实验须关闭历史回调、单任务运行；严格速度结论还需控制硬件负载、热身与执行顺序，现有按组串行 timing 仅是初步测量。

## 可直接执行的命令

```powershell
# 查看/登记 pilot 清单，不启动计算
python scripts/run_iemoeo_mechanisms.py --stage pilot --workers 4

# 执行 720 项内部机制 pilot；已有同配置结果自动跳过
python scripts/run_iemoeo_mechanisms.py --stage pilot --workers 4 --execute

# 所有组完成后，生成两两对照、交互、开关激活和逐运行指标
python scripts/summarize_iemoeo_mechanisms.py results/iemoeo_mechanisms_v1/pilot/core

# 可选敏感性组，先登记检查，再加 --execute
python scripts/run_iemoeo_mechanisms.py --stage pilot --suite sensitivity --workers 4

# 冻结后的独立确认，先登记，不自动执行
python scripts/run_iemoeo_mechanisms.py --stage confirm --workers 4
```

结果使用现有 `results/algorithms/IEMOEO/...` 结果库，组目录只保存清单和失败记录。生产算法标识仍为 IEMOEO；机制汇总仅在内存里换成组名称。登记会保存方案摘要及实现/依赖信息，修改方案或实现后应使用新的 `--output-root`；worker 数可以调整。
