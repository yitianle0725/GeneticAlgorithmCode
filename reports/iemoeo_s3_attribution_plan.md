# IEMOEC / S3-Elite 的归因实验与创新表述路线

S3-Elite 是本仓库 IEMOEC 的实际版本，可以作为提出算法的候选实现，使用 IEMOEC-S3-Elite 名称报告。
已有结果是它的性能证据。实现归属、版本名称与相对文献的新颖性是不同问题；不能把普通 SBX 写成已实现的元素继承，
也不能把方向内繁殖写成已达到数学局部极值。是否保留 S3-Elite 为论文最终实现，应由实际规则、可重复贡献和文献对照决定，
不取决于它被称作“早期”还是“新版本”。

本次新增的是独立的 `IEMOEO --iemoeo-architecture s3_attribution` 候选架构，algorithm schema 4。
它复用 S3 的方向池、算子、归一化、缓存及环境选择组件，在同一执行核心中提供归因开关。
它不是原样的 S3-Elite，也不继承其已有排名。原 S3-Elite 和原 IE-MOEO 继续保留作参照。

## 因素与严格含义

| 因素 | 开启 | 关闭/替代 | 可以检验什么 |
|---|---|---|---|
| I：独立局部搜索 | 每个同步局部子步只从自己的方向池取父代 | 各方向使用同一个冻结共享池，保留方向内更新 | 阶段内封闭交配的贡献，不是永不交换的谱系 |
| P：代表选择 | 在冻结公共归一化与本方向 Tchebycheff 值下选最佳代表 | 同一方向槽位随机代表 | 局部择优是否优于随机选择，不是数学极值认证 |
| C：显式组合 | 不同决策亲本按四个变量块继承，再变异 | 相同新增组合 FE 的 SBX＋相同变异 | 块继承相对 SBX 的贡献；不自动外推为优于所有交叉 |
| M：方向记忆 | 保留并更新跨轮方向微种群 | 每批从当前全局 N 个体重建相同方向、相同容量的池 | 持久方向记忆策略的总贡献 |
| E：方向精英保护 | 按原 S3 规则预留方向精英 | 同一 NSGA3 环境选择，不预留精英 | 额外精英预留是否有益；两组都有常规全局精英候选 |

每批固定方向及公共归一化，默认做三个同步局部子步，结束后才统一选择并交换候选。
跨轮可以更新方向池；因此不声称整个运行都是封闭谱系。I 开关不改变地方保留容量或全局输出容量。
这里的独立指父代取样与局部选择封闭；仍共用随机流和决策去重缓存，不声称各方向的随机过程相互独立。
P 两组使用同样的预定方向槽位与亲本数量上限；实际不同决策数仍须报告，不能用克隆凑有效父代数。

新架构统一从 N 个公共初始决策开始，最终输出相同 N 个个体，指标再按原规则提取非支配部分。
局部总批量为 4N，组合名义配额为批量的 1/4；缓存重复不计新增 FE。
开启 C 的结构化/SBX 配额一致，亲本不足等无法组合的余额转给同一 I 规则的局部搜索并记录。
`no_combination` 把全部组合配额转给局部搜索，检验组合资源分配本身的价值。
总预算相同，不宣称资格检查失败时逐阶段实际 FE 也相同。

## 为什么同时保留历史 S3 对照

`s3_elite_reference` 原样调用 IEMOEC/s3_elite；`s3_hybrid_reference` 原样调用 s3_hybrid。
两者共享方向记忆和 50% 隔离/25% 共享/25% 代表重组配额，精英保护是核心区别，
因此 `historical_s3_elite` 可直接审计历史 S3 的精英保护作用。

新架构与历史 S3 在局部更新、批量、代表选择和组合等处都有区别，`performance_reference` 只作性能比较，
不能将它当单因素对照。M 的纯开关在新统一支撑层内实现，其结论不能自动当成历史 S3 的记忆因果效应。
原 `s3_memory` 与 `s3_hybrid` 还改变了繁殖预算，不能用它们直接替代记忆开关。

## 第一步：支撑机制与核心组合的归因

`screen` 包含 16 组：

- 核心组合 K（I/P/C 同时开或同时关）× M × E 的完整 2×2×2，共 8 组。
- 在 M=E=1 条件下分别关闭 I、将 P 改随机、将 C 改 SBX，新增 3 组。
- 有资格检查、等探测预算但不筛选、无组合，新增 3 组。
- 历史 S3-Elite、S3-Hybrid 两个性能/精英保护参照。

K 是三个规则的策略包，不能把它的收益直接写成每个规则都有效。
先看 K 在四种 M/E 条件下的收益，再看 K×M、K×E、M×E 的交互：

| 观测情形 | 可采用的解释/后续行动 |
|---|---|
| K 在 M=E=0 时仍有正向收益 | 支持核心包不完全依赖这两个支撑机制；各核心仍需独立归因 |
| K 仅在某种 M/E 条件下有收益 | 表述必须写明该成立条件，不能宣传无条件的新原理 |
| M/E 有收益而 K 无收益或有害 | 主要贡献应归于记忆/精英机制；重新审视三个核心的具体规则 |
| E 在历史 S3 和新支撑层都正向 | 精英规则具有跨两个执行框架的开发证据，仍需独立确认 |
| 新 full 不如原 S3-Elite | 保留负面结果；不能借用原 S3 排名证明新算法有效 |

## 第二步：完整区分三个核心与条件依赖

`factorial` 包含 I/P/C/M/E 的完整 2^5=32 个科学配置，加上资格两组、无组合、两个历史参照，共 37 组。
它包含整个 screen，已完成任务跨套件复用；不再重算相同配置。

每个因素的主效应，在每个场景、每个 seed 内，先对其余 16 个背景的配对 log IGD+ 比值等权平均；
再以 seed 为检验单位。不能把 16 个背景当成额外 16 个独立随机重复。
screen 只输出 K/M/E 的完整边际效应；缺少完整 32 组合时，不假装输出 I/P/C 的背景平均主效应。
已有的 I/P/C 单因素比较只适用于 M=E=1 条件。

## 第三步：单独检验“合格极值亲本”

默认 full 使用局部最佳代表，不要求资格探测，所以不能把它写成严格极值算法。
`probe_checked` 与 `probe_unchecked` 都给出 20% 批量的探测配额，在代表的每个坐标正负方向，
按 0.01 倍变量范围构造有限探测点，共用冻结的方向与归一化。评价全部计入总 FE，缓存命中计零。
只有完整探测且未发现超过 1e-12 标量改进时才有数值资格。预算不足、探测未完成、发现改进均不合格。
这只认证“这组坐标探测点未发现改进”，不是连续邻域最优、KKT 或驻点证明，也没有检验所有耦合方向。

checked 只能使用合格父代，且需要至少两个不同决策才能组合；不合格者不会被保底补成极值。
无法组合的配额及未花完的探测额度转给原交配规则的局部搜索。
unchecked 仍执行探测、保留探测候选，但不据资格排除亲本。匹配的是探测策略及名义配额；
缓存命中和筛选后轨迹可能令后续实际探测 FE 不同，须同时报告，不宣称各轮实际探测费用相同。
因此该配对检验含搜索动态中介效应的资格筛选策略，
checked 对默认 full 则检验包含探测成本的整个策略。

若合格者长期不足两个，结论应是当前局部深度、探测半径和预算下极值组合条件不满足，
不能通过取消计费、偷偷使用不合格者或删掉失败场景来制造正面结果。

## 运行顺序、规模与结果

开发问题：DTLZ2/3/7、WFG1/4/9；M=3/5/8；seeds1–5；200N。
选择覆盖了当前薄弱和较好的场景，不只选 WFG4。开发数据已被查看过，不是独立确认集。
screen 名义 1440 项，factorial 名义 3330 项；第二阶段补充最多 1890 项。
现有历史 S3-Elite 在这些条件下的结果会按身份匹配复用，不重跑其他成熟算法。

```powershell
# 默认 screen；先登记确认任务及成本，再开始运行
python scripts/run_s3_attribution.py --stage pilot --workers 4
python scripts/run_s3_attribution.py --stage pilot --workers 4 --execute
python scripts/summarize_iemoeo_mechanisms.py results/iemoeo_s3_attribution_v1/pilot/screen

# 需要完整背景归因时再扩展，已完成的 screen 配置自动复用
python scripts/run_s3_attribution.py --stage pilot --suite factorial --workers 4 --execute
python scripts/summarize_iemoeo_mechanisms.py results/iemoeo_s3_attribution_v1/pilot/factorial

# 中断后只补未完成项
python scripts/run_s3_attribution.py --stage pilot --retry-incomplete --workers 4 --execute
```

从 screen 扩展 factorial 时，已命中共享结果的组也必须在新套件中登记 `experiment_manifest.json`。
调度器现在先写全部组清单，再过滤需要计算的组；即使日志为 `0/37`，也可以正常汇总。
若旧版已完成计算却提示缺少清单，更新后重新执行同一 factorial 续跑命令即可补齐引用，
不需要复制结果目录或使用 `--force`，不会重算已完成 seed。

先完成分析，再决定是否扩展；本次仅运行功能冒烟，不自动启动长 pilot。
5 seeds 不能承担多项两侧精确检验的显著性确认。固定后确认使用独立 seeds61–90、400N，
仍为 M3/5/8，不运行 MOEAD、M10/M15。确认套件要与最终保留的主张匹配，不能只挑 pilot 的有利函数。
若保持 screen 全套确认，任务数为 8640；不是当前必须立即支付的成本。

汇总文件：

- `contrast_overview.csv`：每个配对的数值方向、效应与显著结果分开。
- `interactions.csv`：预登记条件性差中差，负值只表示第一个条件下效应更有利。
- `factorial_effects.csv`：背景平均的 K/M/E 或 I/P/C/M/E 效应。
- `activation.csv`：资格完整性、探测 FE、组合余额、跨岛父代、保护数量等。
- `claim_evidence.md`：具体规则、条件、证据和下一步表述台账。

新架构目前记录专用归因诊断，不采集旧版“目标近、决策远”候选对抽样；
`selection_pair_audit_available=false` 时相关零值表示未采集，不能据此声称避免错杀或没有此类候选。

主对照全部场景和 IGD+/HV 联合 Holm；预登记交互另为一族；边际效应的 package 与 individual
分别作为预登记的两个 IGD+ 检验族，各包含该族全部因素与场景。不能在这些表之间挑最小 p 值作为同一主张的证据。
不把跨问题原始 IGD+ 直接平均，也不根据 pilot 的单次 A12 值宣称充分效果。

## 逐步形成创新表述

现在可以写：研究固定方向局部搜索、代表选择和跨群体元素组合，在同一记忆与环境选择条件下检验贡献及交互。
先把候选规则定义清楚，再等待以下证据：

1. 规则真实执行，预算、输出容量和父代来源可审计。
2. 相对合理替代规则有可重复贡献，并同时报告反例与收益成立条件。
3. 独立确认后，若收益依赖方向记忆或精英保护，标题和结论中保留这个条件。
4. 若块结构要作为独立创新，还应补充同一支撑层中的逐坐标对照，以及结构可组合/破坏结构的控制；当前 C 只比较 SBX。
5. 最后对实际规则做文献对照，明确与已有岛模型、代表选择、交叉、档案方法的区别。仓库实验不能自行认证“首次提出”。

若最终证据主要来自 S3 的记忆与精英保护，应围绕这两个实际有贡献的规则组织算法表述，
不必为了坚持三个名称而把负面或未触发的机制写成创新。S3-Elite 是自己的版本，不妨碍它成为最终候选；
需要的是与实际实现和证据相符的名称与主张。

## 旧结果隔离

原 founder 引擎逐字节迁入 `iemoeo_founder.py`，构造入口按 architecture 选择引擎。
旧算法仍使用旧配置序列化、schema、摘要键和相同执行字节；新架构单独 schema4，摘要包含路由、
新引擎及所用 S3 组件。旧 S3-Elite、公共算法和 320 项原 IE-MOEO 的缓存身份已核对保持有效。
归因使用同一个 run.py / run_case / 结果库核心，新增入口只改变默认实验方案，不另写执行和存储业务。

本次已通过 159 项单元/集成测试，并完成 37 组 × 2 场景的 74 次功能冒烟及严格汇总。
隔离组合的跨岛父代记录为零，共享控制出现跨岛取样；保护开关的预留计数也对应开启/关闭。
资格组累计完整探测了 22 个代表，合格数为零，因此 checked 的组合 FE 为零，864 个名义组合 FE
全部转给局部搜索。这是当前预算下极值前提未满足的观测，不是极值组合有效的证明。
原两例 founder 冒烟重新执行后的最终种群文件完全一致，旧八种算法摘要不变；
新 pilot 中 S3-Elite 的 90 项历史结果全部命中共享缓存。
核对记录保存在 `results/iemoeo_s3_attribution_v1/compatibility_validation.json`。
长 pilot 已登记，尚未启动；上述冒烟不能用作性能或创新性确认。
