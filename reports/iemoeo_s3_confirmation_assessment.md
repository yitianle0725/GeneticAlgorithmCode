# 独立确认结论与冻结版本

本批次为预登记候选 f11011 的独立确认：6 个函数 × M3/5/8 × seeds61–90 × 9 组，共 4860 项、
136404000 FE。完整性、实际 FE、参数和源码摘要核对通过，540 个场景/seed 区块的初始决策摘要一致。
主对照 288 项统一 Holm；整块×记忆交互为独立登记的 18 项检验族。
共有 98 项主对照显著差异，其中包含正面和负面结果，不能把这个总数当作“98 项机制验证成功”。

表中为 18 个场景的“显著有利/未检出显著差异/显著不利”，不是数值中位数胜负：

| 对照（target 相对 control） | IGD+ | HV | 解释 |
|---|---:|---:|---|
| 跨方向 SBX 对继续局部搜索 | 14/4/0 | 13/5/0 | 最强贡献证据；IGD+ 中位数 18/18 场景更好 |
| 方向最佳代表对随机代表 | 7/11/0 | 4/14/0 | 有独立确认支持，非数学极值认证 |
| 局部隔离对共享交配 | 10/8/0 | 5/11/2 | IGD+ 总体正向，HV 存在反例 |
| 持久方向记忆对重建方向池 | 6/8/4 | 3/11/4 | 明确条件依赖，不能称普遍有益 |
| 方向精英保护对普通 NSGA3 选择 | 1/17/0 | 1/17/0 | 支持较有限，未显著不等于无作用或等效 |
| 有记忆时整块继承对 SBX | 1/10/7 | 0/10/8 | 整块继承总体不宜加入当前候选 |
| 无记忆时整块继承对 SBX | 1/17/0 | 1/17/0 | 没有普遍优势的确认 |
| 预选候选对历史 S3-Elite | 4/14/0 | 1/16/1 | 有条件改进，未建立全面支配 |

候选相对 S3-Elite 的 IGD+ 显著改善场景：DTLZ2-M5、DTLZ3-M3、DTLZ7-M8、WFG1-M3。
HV 在 WFG1-M3 显著改善，在 DTLZ2-M8 显著变差。
隔离的 HV 负面场景为 DTLZ2-M8、WFG9-M8。
方向记忆在 DTLZ2 三个目标数和 WFG9-M3 中，IGD+ 与 HV 均显著变差；同时在其他场景有显著收益。
整块×记忆交互在 7 个场景显著为正，表示相对 SBX，整块继承在有记忆背景中更不利，
不是两个机制已经被证实协同增益。

## 哪些检验已完成

预登记九组确认已全部完成，I/P/M/E、组合资源分配和两个记忆背景下的整块对照均已覆盖。
严格资格 Q 没有进入这轮独立确认，先前 pilot 为负面，因此不纳入冻结版本、不将其视为已确认贡献。
新架构中 NSGA3 环境选择始终存在，本轮不能证明它可以被隔离替代。
数学驻点、普遍最优、其他预算/问题家族、网络应用和岛内并行效率不属于这批确认。
若论文限制于当前规则和条件，不要求把所有这些扩展都补完后才能冻结实现。

## 冻结的是什么

冻结预登记的 f11011，命名为 `iemoeo_s3_confirmed_v1`，是一版经过独立检验的研究基线，
不是对所有问题都最优的算法，也不是根据确认集重新拼出一个版本。
配置为：阶段内隔离、方向最佳代表、跨方向 SBX、持久方向记忆、方向精英保护；关闭旧亲本资格检查，
qualification_mode=none，不采用整块继承。每批 4N、局部三子步、组合名义配额 1/4，输出 N 个个体。

M/E 虽非处处有利，仍保留预登记设置以避免根据确认数据后验删除模块。
若下一版要自适应开启记忆、取消保护或调整组合，应另开开发版本，并用未查看的新 seeds 再确认。
不能使用已经查看的 61–90 继续调参后，再把同一数据称为独立确认。

冻结文件 `experiments/iemoeo_s3_frozen_v1.json` 保存全部参数、参数摘要、实际实现/依赖摘要和证据范围。
`--iemoeo-frozen` 仅读取该完整配置，不与命令行机制参数合并，并拒绝参数摘要或实现版本不匹配。
它只作用于 IEMOEO，不改变同一批次的 IEMOEC/S3-Elite 或公共算法配置；原 IEMOEO 默认仍是 founder，
所以不能省略冻结参数后以为运行的仍是此版本。相同科学配置的结果身份不变，可继续复用已有结果。

```powershell
# 扩展函数覆盖的横向开发比较：不运行 MOEAD、M10/M15
python scripts/run.py --preset benchmark_pilot `
  --algorithms NSGA2 NSGA3 RVEA AGEMOEA2STABLE IEMOEC IEMOEO `
  --iemoec-variant s3_elite `
  --iemoeo-frozen experiments/iemoeo_s3_frozen_v1.json `
  --objectives 3,5,8 --seeds 1-5 --evals-per-pop 200 `
  --workers 4 --run-name iemoeo_confirmed_v1_benchmark --dry-run
```

确认任务清单后移除 `--dry-run` 开始运行，随后：

```powershell
python scripts/summarize.py results/iemoeo_confirmed_v1_benchmark --target IEMOEO
```

这轮覆盖全部 16 个标准函数、6 种算法，共 1440 项；多数公共基线和原 S3 结果已经存在，
不会要求重跑前述机制消融。它是扩展问题覆盖的开发比较，5 seeds 不是新的正式横向确认。
本次逐条核对：五种对照算法各 240 项全部可复用，候选可复用 90 项，只需新增 150 项。
已验证全部 540 项确认候选的缓存仍有效；165 项测试通过。新横向批次仅做了 dry-run，未启动计算。

当前可支持的表述：在这六个函数、M3/5/8、200N 条件下，方向最佳代表选择和跨方向重组
相对其替代策略具有独立确认支持，局部隔离具有 IGD+ 收益及 HV 权衡。
不能据此宣称“所有机制都是正向”“采用严格极值资格”“整块继承必需”或“全面超过成熟算法”。

S3-Elite 与原 IE-MOEO 的完整机制对照、融合版本的证据边界及可采用的创新表述，见
[机制与创新评估](iemoeo_mechanism_innovation_assessment.md)。
